一、一分钟看懂：四层结构

从下往上：物理内核 → Python 包 → MCP 服务 → 工作流 skill。你要装的只有中间两层， 最上层的 skill 是可选的。

Agent 你已经有了

Claude Code / Codex / 任何支持 MCP 的 agent。它通过 stdio 调 MCP 工具。

▲

channel-sim skill 要装 可选

一个 SKILL.md，约 290 行。管流程：怎么问用户、什么时候过门、 结论怎么写。不装也能用 MCP，只是 agent 得自己想流程。

▲

superwireless MCP 服务 要装

30 个工具，stdio 传输。管能力：生成信道、出观察量、跑校准、过门、算样本数。 自包含——每个工具的文档字符串里写清了口径与陷阱，不依赖 skill 也能被正确调用。

▲

superwireless Python 包 跟 MCP 一起装

17 个模块、约 6700 行。信道生成、测量量、谱效链路、38.901 校准、三道门。 也可以绕过 MCP 直接 import 当库用。

▲

ChannelHub 物理内核 外部依赖，要单独 clone

3GPP 38.901 的信道生成实现。superwireless 只当它是普通 Python 库， 不用它的后端、前端、数据库、任务队列。

▲

Sionna RT 可选，约 300 MB

射线追踪。不装的话统计信道照常能跑，sw_capabilities 会如实报告缺什么。

MCP 管能力，skill 管流程，两者故意分开。 如果把流程写进 MCP，别人的 agent 就被迫按我的节奏走； 如果把能力写进 skill，不装 skill 的 agent 就什么都做不了。 所以 MCP 做到自包含，skill 只做编排——两边都能单独工作。

二、要装的东西一共三样

装什么怎么装体积不装会怎样
ChannelHub
物理内核		 git clone 到 superwireless 的同级或上级目录~50 MB 不能用 所有信道生成都依赖它

Python 依赖

Python ≥ 3.10。pip install -e . 会带上这六个：

numpy ≥1.24
scipy ≥1.10
pydantic ≥2.0
pyyaml ≥6.0
structlog ≥23.0
mcp ≥1.0

都是常见包，不锁死版本。sionna-rt 会连带装 mitsuba + drjit， 实测不会降级已有的 numpy / scipy / torch。

二点五、分发给别人：两条路

自己装看第三节。要把这东西给别人用，走下面两条之一。

① 外网用户：一句话交给 agent

让用户把这句话发给自己的 Claude Code / Codex：

帮我装 superwireless：读
https://github.com/TianLin0509/superwireless/blob/main/INSTALL_AGENT.md
按里面的步骤装好并验证，装完告诉我能不能用。

INSTALL_AGENT.md 是写给 agent 看的，不是给人看的： 每步带验证命令与预期输出，明确标了哪些事该问用户、哪些该自己跑命令查， 最后附一张失败对照表。

② 内网用户：离线 .zip

在能联网的机器上打包：

python scripts/make_offline_bundle.py
# → …-full-win_amd64-py3.12.zip  65 MB  全新 venv 可全程离线装

python scripts/make_offline_bundle.py --thin
# → …-thin-win_amd64-py3.12.zip  17 MB  要求目标机已有 numpy/scipy

接收方解压后，把 开始安装.txt 里那句话发给自己的 agent 即可， 全程不需要联网。

离线包里有什么

内容说明
开始安装.txt给人看的一句话说明 + 需要自备什么
INSTALL_AGENT.md给 agent 看的安装步骤，自动识别离线模式
wheels/依赖的 wheel。装的时候 pip install --no-index --find-links wheels -e .
源码 + skill + presets + tests与仓库一致，去掉了 __pycache__ 与 artifacts/
bundle-manifest.json包型、commit、平台、各 wheel 与关键文件的 SHA-256。requires_preinstalled 直接列出需自备什么
三份 HTML 文档SETUP / CAPABILITIES / SHOWCASE，离线可开

离线包不含 ChannelHub。该仓库没有 LICENSE 文件， 按默认规则是保留所有权利，随包转发有法律风险。

接收方需要自备一份，判据是目录下存在 src/msg_embedding/data/contract.py。INSTALL_AGENT.md 里 写了在内网常见位置搜索它的命令；找不到就会停下来问用户。

确认自己有权分发时（公司内部本来就有这份代码、或已获授权）， 用 --include-channelhub <路径> 打进去。

wheel 是平台相关的。numpy、scipy、pydantic-core 都带编译好的二进制， 在 Windows 上下的包拿到 Linux 上装不了。所以 zip 文件名里带了平台和 Python 版本， 必须在与目标机器同平台、同 Python 大版本的机器上打包。

跨平台打包用 --platform manylinux2014_x86_64 --python-version 3.11，pip 会去下对应平台的轮子。

默认打完整包。早先默认打的是轻量包（不含 numpy/scipy）， 实测它在全新 venv 里连 pip install --no-index -e . 都起不来—— 先卡在缺构建后端 setuptools，而 pip 只说 "install build dependencies did not run successfully"，完全看不出缺什么。

现在完整包连构建后端一起带（37 个 wheel、65 MB）， 实测全新 venv 里只有 pip 也能装上，35 个包全离线。 轻量包必须显式 --thin，包型写进文件名与 manifest。

整条链路是实测过的，而且按环境分开报：

full 包 —— 全新 venv（安装前只有 pip）→ pip install --no-index --find-links wheels -e . 装上 35 个包（含 superwireless 自身）→ manifest 里 10 个文件 + 37 个 wheel 的 SHA-256 逐一核对， 零不一致 → 无 ChannelHub 时三个引擎都如实报 unavailable、MCP 仍能 list 出 30 个工具 → 放入 ChannelHub 后 test_e2e 39 / test_mcp_server 25 / test_gates 86 全通过 （mcp 2.0、无 sionna-rt）。

thin 包 —— 按文档不加 -e . 装上 31 个运行时依赖；import numpy 明确报 ModuleNotFoundError，开始安装.txt 首屏就写明"本包为轻量包、 要求目标机已有 numpy/scipy"。不伪装成自包含。

这一跑还抓到一个真 bug：mcp 2.0 删掉了 mcp.server.fastmcp，新装的用户会在 import 阶段就崩。 开发机上装的是 1.27 所以一直没暴露。现已兼容两个版本。

三、完整安装步骤

拿两个仓库，放成兄弟目录

# 目录关系随意，但放成兄弟目录时 superwireless 能自动找到 ChannelHub
cd ~/code
git clone https://github.com/wangxz0803-lab/ChannelHub_main
git clone https://github.com/TianLin0509/superwireless

自动发现的查找顺序：环境变量 SUPERWIRELESS_CHANNELHUB → superwireless 的父目录、祖父目录、自身目录下名为 ChannelHub_main / ChannelHub / channelhub 的目录。 判据是里面有没有 src/msg_embedding/data/contract.py。

放在别处就设环境变量：

# Windows PowerShell（写进用户环境变量才能持久）
[Environment]::SetEnvironmentVariable("SUPERWIRELESS_CHANNELHUB", "D:\path\to\ChannelHub_main", "User")

# macOS / Linux
export SUPERWIRELESS_CHANNELHUB=/path/to/ChannelHub_main

装 superwireless

cd superwireless
pip install -e .

# 可选：射线追踪（约 300 MB，含 mitsuba + drjit）
pip install sionna-rt

-e 是可编辑安装，改代码不用重装。其实 MCP 服务器脚本是自包含的 （自己会把 src/ 加进 sys.path），所以 pip install -e . 主要作用是把那六个依赖装齐。

注册 MCP 服务

指向仓库里的 scripts/mcp_server.py，用绝对路径：

Claude Code
claude mcp add superwireless -- python /abs/path/to/superwireless/scripts/mcp_server.py
Codex
codex mcp add superwireless -- python /abs/path/to/superwireless/scripts/mcp_server.py

Codex 也可以直接改 ~/.codex/config.toml：

[mcp_servers.superwireless]
command = 'C:\path\to\python.exe'
args = ['C:\path\to\superwireless\scripts\mcp_server.py']

Windows 上把 python 换成 python.exe 的绝对路径。 装了多个 Python 版本时，agent 起的子进程未必用你 pip install 那个， 表现是"MCP 连上了但一调用就说缺依赖"。

装 skill（可选，但推荐）

# Claude Code
cp -r skills/channel-sim ~/.claude/skills/

# Codex
cp -r skills/channel-sim ~/.codex/skills/

# Windows PowerShell
Copy-Item -Recurse skills\channel-sim $HOME\.claude\skills\
Copy-Item -Recurse skills\channel-sim $HOME\.codex\skills\

就一个 SKILL.md 文件，没有脚本、没有依赖。改了记得三份同步 （仓库 + 两个 agent 目录）。

验证

claude mcp list          # 应看到 superwireless ... ✔ Connected

cd superwireless
python tests/test_e2e.py         # 端到端 39 项
python tests/test_mcp_server.py  # MCP 全链路 33 项
python tests/test_raytracing.py  # 射线追踪与决策层 39 项
python tests/test_linklevel.py   # 谱效、可信度、物理层 35 项
python tests/test_gates.py       # 校准、标准表、三道门 86 项
python tests/test_results.py     # 结果索引与取货 80 项
python tests/test_linkadapt.py   # 链路自适应、吞吐、并行生成 135 项
python tests/test_interference.py # IoT、测量域、场景预设、探测模式、文档计数 145 项

共 592 项。测试会真的跑仿真；当前开发环境全跑一遍约 2 分钟，安装环境不同会有波动。 没装 sionna-rt 时 test_raytracing.py 里的射线追踪部分会自动跳过并说明原因。

阶段工具作用

sw_list_datasets本机已生成的数据集
说明书sw_spec_sheet把敲定的配置画出来：阵列/拓扑/频域/时域/信道剖面示意图 + 逐项标注来源的参数全表。离线 HTML，落在 artifacts/specs/

七、跑起来会产生什么、放在哪

全部落在仓库的 artifacts/ 下，已在 .gitignore 里，不会污染仓库。

目录内容本机现状能删吗
artifacts/datasets/<id>/ channels.npz（信道与标量）+ summary.json（配置、统计、计划书） 391 MB能 删了重新生成即可
artifacts/drafts/配置草稿（协商过程的中间态）500 KB 能
artifacts/scenes/射线追踪场景资产缓存658 KB 能但会重新准备 首次用中国城市场景要重新处理几十秒

体积估算。单样本 ≈ T × RB × BS_ant × UE_ant × 8 字节 × 2（理想 + 估计两份）。 64 天线 × 273 RB × 4 收 的样本约 1.1 MB，200 个就是 220 MB。 sw_plan 会先给体积预估，超过 1 GB 时应当提醒。

数据永远不进对话。MCP 只回句柄、统计摘要和取货代码。 一个样本序列化成 JSON 会膨胀到十几 MB——放进上下文既装不下也没意义。 拿到 sw_deliver 的代码后写进脚本运行，不要试图打印数组。

八、三种用法：按需取用

① MCP + skill推荐

完整体验。agent 会主动问清空槽、按流程过三道门、在结论里带上置信区间， 过不了门时明说"结论不成立"。

适合：正经跑蒙特卡洛、结论要拿去汇报或写论文。

② 只装 MCP

30 个工具全都在，只是没人提醒流程。agent 仍然读得到每个工具文档里的口径说明， sw_gate 也照样会拦。

适合：你自己清楚要什么，或者用的 agent 不支持 skill。

③ 直接当 Python 库

不注册 MCP，直接 import。所有能力都有对应的函数。

from superwireless import load
ds = load("ds_xxxx")
print(ds.gate().text())
print(ds.calibrate().text())
r = ds.compare_arms(
    {"name":"我的","method":"svd_wideband","csi":"estimated"},
    {"name":"基线","method":"type1","csi":"estimated"})
print(r.statement())

适合：写脚本批量跑、接进已有的仿真工程。

九、装完先跑这几条

验证链路通了

# 1. 引擎可用性 —— 缺什么会如实说，不会假装能跑
sw_capabilities()

十、排错

症状原因怎么办
MCP 连不上Python 路径不对，或依赖没装齐 用 python.exe 绝对路径注册；先手动跑一次 python scripts/mcp_server.py 看报什么错（stderr 会打印预热结果）
MCP 连上了但一调用就报缺依赖agent 起的子进程用的不是你 pip install 的那个 Python 同上，换成绝对路径
报找不到 ChannelHub目录不在查找范围内 设 SUPERWIRELESS_CHANNELHUB 指到 ChannelHub 根目录 （里面要有 src/msg_embedding/data/contract.py）
sw_generate 卡住不返回历史上是 scipy 在工作线程里的 import 死锁 已修（启动时预热）。若仍遇到，设 SUPERWIRELESS_DEBUG=1 会开 faulthandler 并把栈打到 stderr
射线追踪报 invalid PLY header中国城市场景的 PLY 是 VTK 导出的，Mitsuba 3.8 解析不了 已自动处理（复制到缓存后清理头部，不动原文件）。加新城市场景时若再遇到就是这个原因
门 1 老是不过多半是真的有问题，不是误报 看 detail 字段——它会写清偏差多少、容差依据、怎么改。 最常见是场景与信道剖面的视距类别不匹配
离线装报 install build dependencies did not run successfully用 thin 包做了 pip install -e .，缺构建后端 setuptoolsthin 包别加 -e .，直接装依赖；或改用 full 包
服务端报 No module named 'mcp.server.fastmcp'装到了 mcp 2.x，该模块已被删除升级 superwireless 到含兼容层的版本；或退回 pip install "mcp<2"
生成很慢射线追踪比统计信道慢一个量级 统计信道约 0.2 秒/样本，射线追踪 2~6 秒/样本。先跑 20 个探路
